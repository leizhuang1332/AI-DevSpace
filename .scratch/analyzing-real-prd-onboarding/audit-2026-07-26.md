## 关键阻塞项

### 1. 真实首次访问可能看不到"开始分析"

CTA 的显示条件要求：

- `sessions.length === 0`

见 [analyzing-zone.tsx:720-735](apps/web/src/components/analyzing-zone.tsx#L720-L735)。

但是 server loader 在没有 `_index.yaml` 时会生成一个默认 session，而不是返回空数组：

- [analyzing.server.ts:748-792](apps/web/src/lib/analyzing.server.ts#L748-L792)

因此真实"有 requirement、没有分析 session"的首次访问可能得到 `sessions.length === 1`，按钮不会显示。现有测试使用手工构造的 `sessions: []`，没有覆盖真实 server-to-component 数据链路。

---

### 2. SDK 输出没有转成结构化产品数据

真实 SDK 的 text 事件目前统一写为：

- `kind: 'narration'`
- 无 `source_refs`

见 [analysis.ts:1049-1070](apps/agent/src/routes/analysis.ts#L1049-L1070)。

但 ProductList 只消费：

- `subproblem`
- `risk`
- `option`

见 [analyzing.ts:507-520](apps/web/src/lib/analyzing.ts#L507-L520)。

目前没有 production parser 将 Skill 输出中的：

- `[DIM ...]`
- `[SUBPROBLEM]`
- `[RISK]`
- `[OPTION]`
- `source_refs`

转换成对应的结构化 chunk。

这意味着：

- AdmissionDashboard 五卡不会随着 SSE 上涨；
- ProductList 不会出现 subproblem/risk/option；
- ticket 07 的强断言无法满足。

这是当前最高优先级的功能缺口。

---

### 3. 双 turn 的真实错误路径可能挂死

`runTurn` 在 `session.send()` 抛错后仍然无条件等待事件流结束：

- [analysis.ts:1130-1137](apps/agent/src/routes/analysis.ts#L1130-L1137)

如果 AISession 已进入 `errored`，后续 `send()` 会在产生 `done` 事件之前直接抛错：

- [AISession.ts:273-279](apps/agent/src/session/AISession.ts#L273-L279)
- [AISession.ts:487-531](apps/agent/src/session/AISession.ts#L487-L531)

此时等待事件流的 Promise 可能永远无法结束，导致：

- turn 2 不执行；
- session 不关闭；
- analysis job 长时间处于 running。

现有 fake provider 测试只覆盖了"空输出但正常 done"，没有覆盖真正的 `send()` reject 或 SDK error。

---

### 4. Snapshot 默认处于关闭状态

Snapshot root 依赖 `AIDEVSPACE_SNAPSHOT_DIR`，未配置时直接 no-op：

- [analysis-snapshot.ts:63-66](apps/agent/src/routes/analysis-snapshot.ts#L63-L66)
- [analysis-snapshot.ts:90-109](apps/agent/src/routes/analysis-snapshot.ts#L90-L109)

默认启动脚本没有设置该变量：

- [agent-start.sh:5-35](packages/scripts/agent-start.sh#L5-L35)

所以正常启动应用时：

- 不会生成 snapshot；
- snapshot 列表为空；
- restore 可能返回 `snapshot_dir_unset`。

另外，StatusBar 只在 `reqId` 变化时加载一次 snapshot：

- [statusbar.tsx:38-58](apps/web/src/components/statusbar.tsx#L38-L58)

分析过程中生成 snapshot 后，`reqId` 不变，列表不会自动刷新。首次加载为空时，回滚入口本身也不会出现。

### 5. 真跑 E2E 没有真正闭环

Ticket 07 已创建：

- [analyzing-real-run.spec.ts](apps/web/e2e/analyzing-real-run.spec.ts)
- [verify-analyzing-real-run.sh](scripts/verify-analyzing-real-run.sh)

但仍有以下问题：

1. Playwright spec 不会自行启动 web 和 agent；
2. Playwright 配置在服务不可达时会 skip；
3. 仓库中没有 CI workflow 调用该 E2E；
4. 现有提交记录只表明未设置 API key，因此测试被跳过；
5. 没有截图、SSE、`chunks.jsonl` 或其他真 SDK 成功 artifact；
6. 当前 CTA 和结构化输出缺口使该 spec 即使真跑也难以通过。

此外 reviewer 脚本是先 POST、后订阅 SSE，与 ticket 00 修复的顺序相反，可能丢失早期事件。
