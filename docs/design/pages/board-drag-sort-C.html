■ 蓝色背景 = 可拖区(card-top 整行 = id 短哈希 + 菜单)   ■ 红色背景 = 不可拖区(title 主体 + meta 行)

vs 方案 A 关键差异: • 触发器:从「左侧 ⋮⋮ 6 点 sprite」移除,改为「card-top 整行(id 短哈希 + 菜单)」。 • 视觉反馈:.card-top hover 时显 brand-50 背景 + 2px brand 顶线(Linear 风格),告诉用户"这里可拖"且不挤压 padding。 • 键盘 focus:.card:focus-visible 显 2px outline + 4px brand-50 outer shadow,与决策 24 / 30 a11y 一致。 • 触发器面积:id 短哈希(~50px) + 空白中间 + 菜单(~20px) ≈ 卡片宽 100% × 一行高度 ≈ 240px × 24px。比 A 的 `⋮⋮ 6 点 12px` 大 40 倍。 • 不可拖区:title 主体 + meta 行;click 行为仍为点击进详情。 • 拖拽中视觉:同 C 方案 = ghost scale(1.04) + placeholder 虚线 + 让位 200ms。 • 提示词:cursor: grab 在 card-top 区域、cursor: pointer 在其他区域(点击进详情)。
方案 C · 视觉规则 · id 区触发 + Notion 2024
• 触发器:仅 .card-top 整行(包含 id 短哈希 + 菜单 ⋯);cursor: grab,hover 显 background: var(--brand-50) + 2px brand 顶线(box-shadow: inset 0 2px 0 var(--brand))。
• 不可拖区:title 主体(.card-title,2 行)和 meta 行(.card-meta)完全不绑 listeners;click 仍触发进详情。
• 键盘 focus 状态:.card:focus-visible 显 outline:2px solid var(--brand) + outline-offset:2px + box-shadow:0 0 0 4px var(--brand-50);card-top 同步显 brand-50 + 2px 顶线。
• 菜单 click 行为:@click.stopPropagation 同 A(避免点菜单误触拖拽 / 详情跳转)。
• ghost 视觉:transform:scale(1.04) rotate(2deg) + box-shadow:0 16px 40px rgba(94,106,210,.30) + 2px brand border(在 DragOverlay 渲染)。
• placeholder:目标列 column-slot 内插入 2px 虚线 + brand-50 背景 + 高度固定 120px;文案 "释放此处 →"。
• 让位动画:目标列内卡片 transform:translateY(8px) + opacity:0.7;200ms ease-out。
• 移动阈值:PointerSensor { activationConstraint: { distance: 5 } }(5px 内仍识别为 click)。
• 冲突 UI:复用 StatusConstraintModal(零改动),拖拽中无预提示(D6 锁定)。
• 库依赖:@dnd-kit/core + sortable + utilities;让位动画用 CSS transition(200ms),无需 framer-motion。
• 关键优势:id 区已有「区分卡片」语义(短哈希是卡片身份 primary key),用户天然知道"这是卡片 ID 区,可拖";2px 顶线 + brand-50 双重信号不挤压 padding。
