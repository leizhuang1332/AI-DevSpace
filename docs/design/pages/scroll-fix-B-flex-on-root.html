关键点 · 风险 · 验收

  • i组件自包含
    AnalysisIssueList 自带 flex sizing,放在任何 flex-col 父容器里都能正确占满剩余空间。不依赖外部 wrapper 模板。
  • !动 caller
    DesktopLayout + NarrowLayout 各一处 caller 改写。e2e / visual regression 都要重跑,确认 dim 蒙层位置 / z-index 没被波及。
  • i语义对齐
    RunSummary / RunLog 都是裸组件放 flex 容器里(flex: 0 1 auto),AnalysisIssueList 走 flex-[2] min-h-0 一致 —— 三者平级。
  • ✓未来可复用
    之后若要把 AnalysisIssueList 嵌进其它模块(比如 DASHBOARD 的 issue widget),不用记得外面套 wrapper div。
  • !建议补短 ADR
    「组件自管 flex sizing」是契约变更(分析区 wrapper 模板废除),未来 reviewer 看 git blame 时会问"为什么这个组件要 self-manage flex" —— 值得一段 ADR。
  • ✓测试覆盖
    vitest: 33 条 Issue 时 outer 高度 === 父容器 flex 分配高度。e2e: 窄视口滚到底后 #33 标题进入视口。
