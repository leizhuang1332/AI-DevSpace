关键差异对比表 4 位置

维度 ① 主区右上角 ② ZoneBar 同行 ③ 识别产物列头 ④ StatusBar 内
符合决策 24"克制在场" 完美 高 中（属识别产物上下文） 低（与 AI 状态混淆）
按钮可见性 高（FAB 永远在视野内） 高 中（小、易忽略） 低（与同行文字混排）
不挤压主区 ✅（绝对定位,零占位） ✅（不占主区） ✅（列头内,只占列头高度） ✅（StatusBar 内）
展开面板方向 左下（自然） 正下 左侧（覆盖到 PRD 列） 正下
面板覆盖 [识别产物] 覆盖（dim 该列） 覆盖 反向（覆盖到 PRD 阅读器） 覆盖
与其他 UI 元素的语义混淆 无 与工具按钮（导出/分享） 与列头 N 计数 与 AI 状态指示
窄视口兼容 ✅ ZoneBar 横向溢出 窄列头装不下 同行文字变拥挤
z-index/层级管理 z-10/20 简洁 需要 portal（跨 ZoneBar） 列内 z 即可 需要 portal（跨 StatusBar）

📌 推荐：① 主区右上角绝对浮动

理由（基于决策表）：

  1. 零层级污染：① 用 `absolute top-3 right-3` 钉在主区容器内,不跨 ZoneBar/StatusBar 边界。②④ 都需要 React Portal 把面板传到 body 才能不被 ZoneBar/StatusBar 的 overflow:hidden 截断,实现复杂。
  2. 最强"克制在场"信号：FAB 是 Linear/Notion 的克制召唤范式;② 是工具按钮,③ 是次要信息,④ 与 AI 状态混排——四者中只有 ① 是"专属召唤"。
  3. 面板方向最自然：① 在右上 → 面板从左下展开,正好覆盖到 [识别产物] 列之上(用户视线移动最短);③ 反向覆盖到 PRD 阅读器(违反"召唤靠近目标"直觉)。
  4. 窄视口天然兼容：FAB 始终在右上,窄视口下不会被挤掉;② 的 ZoneBar 横向溢出、③ 的列头宽度、④ 的同行文字都会在窄视口下出问题。
后续 grill 待解决：① 按钮的精确样式(图标+文字+ N,还是只图标+N)?展开面板最大高度(覆盖到 [识别产物] 哪一行止)?点击面板外/按 Esc 是否关闭?Cmd+K 是否增加"历史分析"快捷命令作为发现路径?
